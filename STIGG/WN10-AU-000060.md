# 📄 WN10-AU-000060 - Audit Logon/Logoff: Group Membership (Success)

## 📌 Control ID
**WN10-AU-000060**

## 🛡️ Description
Windows 10 must be configured to audit **Logon/Logoff - Group Membership** successes.  
This setting helps track the security groups a user belongs to at the time of logon, which is crucial for determining access permissions and security context.

## ✅ STIG Requirement
> *The system must be configured to audit successes for "Group Membership" under the "Logon/Logoff" category.*

## 🎯 Rationale
Auditing group membership on logon provides visibility into the user’s authorization level at the time of login. This can help validate whether a user had the appropriate permissions to access resources or perform actions, aiding in forensic and security investigations.

---

## 🔧 Fix Text

### 📂 Group Policy Editor Method

1. Open the **Group Policy Management Console** (`gpedit.msc`).
2. Navigate to:  

Computer Configuration → Windows Settings → Security Settings →
Advanced Audit Policy Configuration → System Audit Policies → Logon/Logoff

3. Locate and double-click: **Group Membership**.
4. Check the **Configure the following audit events** box.
5. Select **Success** (you may also select **Failure** if needed).
6. Click **OK**, then close Group Policy Editor.
7. Run the following to apply changes:
```

bash
gpupdate /force

🔍 Audit Verification

✅ PowerShell Command
To verify current audit settings, run:

AuditPol /get /category:"Logon/Logoff"
Expected Output:

Group Membership        Success
🖥️ Optional: Registry Check

Although AuditPol is the preferred method, advanced users can explore:

HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit

💡 Notes

Events are logged in Event Viewer under the Security log with Event ID 4627.
Be mindful of audit log size if enabling multiple categories.
