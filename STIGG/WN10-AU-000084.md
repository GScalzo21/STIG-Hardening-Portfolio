📄 WN10-AU-000084 - Audit Object Access: Other Object Access Events (Failure)

📌 Control ID - WN10-AU-000084

🛡️ Description

Windows 10 must be configured to audit Object Access - Other Object Access Events failures.
This ensures that access attempts to certain system objects (such as registry keys, services, printers, and file system objects) are logged when they fail. This information can help identify unauthorized access attempts or misconfigurations and supports forensic analysis during incident response.

✅ STIG Requirement

The system must be configured to audit failures of Object Access events related to "Other Object Access Events".

🎯 Rationale

Auditing failed object access events provides visibility into potential unauthorized attempts to access sensitive system components. This can help detect insider threats, policy violations, and attempts to exploit misconfigurations.

🔧 Fix Text

Group Policy Editor Method
Open the Group Policy Management Console (gpedit.msc).

Navigate to:

Computer Configuration → Windows Settings → Security Settings → Advanced Audit Policy Configuration → System Audit Policies → Object Access.
Find and double-click: Other Object Access Events.
Check the Configure the following audit events box.
Select Failure (you may also select Success if required).
Click OK, then close Group Policy Editor.

Run gpupdate /force in Command Prompt to apply changes.

🔍 Audit Command

To check current settings, run the following in PowerShell:
AuditPol /get /category:"Object Access"

✅ Expected output should include:
Other Object Access Events      Failure

🖥️ Registry Check (Alternative)
Check the following registry path:
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit
Or, use this PowerShell snippet to validate:

$audit = AuditPol /get /subcategory:"Other Object Access Events"
$audit

💡 Notes

If your system is managed via Active Directory, configure this setting in a GPO linked to the appropriate OU.
Be mindful that excessive auditing can increase log size. Always monitor your Event Viewer → Security Logs.
