# WN10-CC-000290: Require High‑Level Encryption for RDS Client Connections

> **Warning!** Audit Deprecated  
> This audit has been deprecated and will be removed in a future update.

## Information  
Remote Desktop Protocol (RDP) transmits screen, input, and clipboard data over the network. Without strong encryption, this data can be intercepted or tampered with. Configuring RDS to require high‑level encryption ensures all RDP traffic is protected with robust ciphers.

## Solution  
Enable and configure the **Set client connection encryption level** policy to **High Level** (FIPS-compliant where required).

### Policy Path  
```text
Computer Configuration
└─ Administrative Templates
   └─ Windows Components
      └─ Remote Desktop Services
         └─ Remote Desktop Session Host
            └─ Security
               └─ “Set client connection encryption level”
```

Locate “Set client connection encryption level”
In the Security folder, find the policy named Set client connection encryption level.
Enable and Configure Encryption Level

Double‑click the policy.
Select Enabled.
Under Options, choose High Level (or FIPS Compliant if mandated).

Click OK.

(Optional) Require Secure RPC Communication
In the same Security folder, locate Require secure RPC communication.

Double‑click, select Enabled, and click OK.
Apply and Refresh Policies
Open an elevated Command Prompt and run:
gpupdate /force

Verify Configuration

On the RDS host, open an elevated PowerShell prompt and run:
Get-ItemProperty -Path "HKLM:\Software\Policies\Microsoft\Windows NT\Terminal Services" `
  -Name MinEncryptionLevel, fEncryptRPCTraffic

Confirm:
MinEncryptionLevel is set to 3 (High) or 4 (FIPS).
fEncryptRPCTraffic is set to 1 (if secure RPC was enabled).

Test an RDP Session

From a client, initiate an RDP connection and verify the session uses TLS 1.2 (or higher) encryption via rdpdiag or network capture tools.
